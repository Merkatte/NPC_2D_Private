# Systems 문서 안내

`Systems`는 기능별 현재 구현을 기록하고 관련 없는 코드 탐색을 줄이는 작업 지도다.

## 읽기 원칙

1. `ProjectStructure.md`에서 작업에 해당하는 기능 문서를 선택한다.
2. 기능이 폴더라면 `README.md`의 하위 기능 표에서 필요한 폴더 또는 leaf 문서를 선택한다. 폴더를 선택했으면 그 폴더의 README에서 선택을 반복하여 필요한 leaf에 도달한다.
3. leaf 문서의 `변경 유형별 최소 확인 범위`를 따라 실제 파일을 연다.
4. 구조·C#·게임 규칙에 해당할 때만 루트 공통 문서를 추가로 읽는다.

상위 인덱스는 모든 leaf나 모든 코드를 읽으라는 뜻이 아니다.

## 현재 기능 지도

| 대기능 | 책임 |
|---|---|
| [NPC](NPC/README.md) | NPC 개체의 공통 수명·판단·실행·표현 |
| [Settlement](Settlement/README.md) | 정착지 건설·건축가 작업·주거·시청 모집 |
| [Economy](Economy/README.md) | 농사·아이템·공유 자원·물류·상단 거래 |
| [Combat](Combat/README.md) | 공통 감지·공격·직군 판단과 성벽 방어 |
| [World](World/README.md) | 경로 탐색과 목적지·provider 공통 계약 |
| [UI](UI/README.md) | 입력·표시 수명·구체 view·시각 규칙·지역화·카메라 조작 |

각 README는 바로 아래 기능을 안내한다. 하위 폴더의 깊이는 책임에 따라 달라지며, 실제 구현 상세와 주 소유 파일은 leaf에서 확인한다.

## Leaf 문서 형식

모든 leaf 문서는 다음 내용을 가진다.

1. 기능 목적과 책임 경계
2. 현재 실행 흐름
3. 주 소유 스크립트 전체 목록과 한 줄 책임
4. 변경 유형별 최소 확인 파일
5. 불변 규칙
6. Unity 배선과 검증 도구
7. 알려진 제약과 TBD
8. 관련 문서
9. 문서 갱신 조건

하나의 production C#은 한 문서에서만 `주 소유 스크립트`로 등록한다. 공유 소비자는 파일 설명을 복사하지 않고 주 소유 문서에 링크한다.

## 계층 분할 기준

### 배치와 깊이

- `Systems/` 바로 아래에는 전체 안내 `README.md`와 대기능 폴더만 둔다. 새 leaf나 이동 안내 문서를 루트에 추가하지 않는다.
- 각 기능 폴더에는 `README.md`를 두고, 그 아래에 하위 기능 폴더 또는 최종 상세 문서인 leaf `.md`를 배치한다.
- 하위 기능이 크면 그 안에 하위 기능 폴더를 다시 둔다. 이 규칙은 모든 깊이에 동일하게 적용하며, 대기능·중기능·소기능의 고정 3단계나 최대 깊이를 두지 않는다.
- 형제 기능의 깊이는 달라도 된다. 한 폴더 안에 독립된 leaf와 더 세분된 하위 기능 폴더를 함께 둘 수 있다.
- 새 문서는 책임이 맞는 기존 기능 폴더 안에 먼저 배치한다. 기존 분류로 설명할 수 없는 책임이 생기면 적절한 부모 아래에 새 기능 폴더를 만든다.

### 분할 판단

세부 기능은 다음 세 조건을 모두 만족하는 책임 단위다.

- 다른 기능과 구분되는 자체 실행 흐름이나 판단 책임이 있다.
- 변경 진입점과 관련 파일 집합을 따로 지정할 수 있다.
- 형제 기능을 수정하지 않고 독립적으로 변경될 수 있다.

한 leaf에 독립 세부 기능이 4개 이상 생기면 그 leaf를 기능 폴더의 README와 하위 문서로 분할한다. 분할된 하위 기능도 같은 기준으로 다시 나눌 수 있다. 4개는 leaf 분할을 반드시 수행하는 기준이며, 상위 기능을 묶는 폴더를 만들기 위한 최소 개수는 아니다.

폴더 안의 하위 기능들도 서로 다른 책임 묶음으로 나뉘고 선택표가 그 묶음을 구분해야 한다면 중간 기능 폴더를 추가한다. 각 폴더는 부모보다 좁은 책임과 하위 기능 선택 기준을 설명할 수 있어야 한다. 파일 수·줄 수·깊이 맞추기만을 위해 나누거나, 같은 책임과 이름을 반복하는 중간 폴더를 만들지 않는다.

```text
Systems/
  README.md
  Feature/
    README.md
    SmallFeature.md
    SubFeature/
      README.md
      Detail.md
      NestedFeature/
        README.md
        DetailA.md
        DetailB.md
```

위 이름은 구조 예시다. 실제 폴더와 leaf는 담당 기능을 드러내는 이름을 사용한다.

### README와 leaf의 책임

- 각 README는 해당 범위의 목적·책임 경계, 바로 아래 폴더와 leaf의 선택표, 하위 기능 사이의 흐름·의존성을 안내한다. 상위 README는 모든 자손 문서나 스크립트의 전체 목록을 복사하지 않는다.
- 실제 상세 흐름, 주 소유 스크립트, 변경 유형별 최소 확인 범위는 leaf가 소유한다. 여러 하위 기능이 공유하는 구현도 책임에 맞는 leaf 한 곳에서 소유하고 소비 문서가 링크한다.
- 폴더 깊이는 기능의 포함 관계를 나타내며 코드의 호출·의존 방향을 뜻하지 않는다. 다른 기능과의 의존성은 문서의 링크와 설명으로 명시한다.
- leaf를 폴더로 분할하거나 문서를 이동할 때에는 부모 README의 선택표와 활성 문서·지침의 링크를 함께 갱신한다. `ProjectStructure.md`의 작업별 경로도 실제 진입점에 맞춘다. 역사 문서의 당시 경로는 보존한다.

## 작성 규칙

- 현재 구현, 계획, TBD를 같은 문단에 섞지 않는다.
- 긴 코드를 복사하지 않고 symbol과 경로를 적는다.
- line number는 장기 문서에 고정하지 않는다.
- 과거 구현 과정은 `Status`, 완료 계획은 `Archive/Plans`에 기록한다.
- leaf 문서는 250줄 이하를 기본으로 하되 정보 삭제로 수치를 맞추지 않는다.
- 코드와 문서가 다르면 코드를 현재 사실로 보고 같은 변경에서 문서를 교정한다.
