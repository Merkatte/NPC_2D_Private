# Systems 문서 안내

`Systems`는 기능별 현재 구현을 기록하고 관련 없는 코드 탐색을 줄이는 작업 지도다.

## 읽기 원칙

1. `ProjectStructure.md`에서 작업에 해당하는 기능 문서를 선택한다.
2. 기능이 폴더라면 `README.md`의 세부 기능 표에서 leaf 문서 하나를 선택한다.
3. leaf 문서의 `변경 유형별 최소 확인 범위`를 따라 실제 파일을 연다.
4. 구조·C#·게임 규칙에 해당할 때만 루트 공통 문서를 추가로 읽는다.

상위 인덱스는 모든 leaf나 모든 코드를 읽으라는 뜻이 아니다.

## Leaf 문서 형식

모든 leaf 또는 단일 기능 문서는 다음 내용을 가진다.

1. 기능 목적과 책임 경계
2. 현재 실행 흐름
3. 주 소유 스크립트 전체 목록과 한 줄 책임
4. 변경 유형별 최소 확인 파일
5. 불변 규칙
6. Unity 배선과 검증 도구
7. 알려진 제약과 TBD
8. 관련 문서
9. 문서 갱신 조건

하나의 production C#은 한 문서에서만 `주 소유 스크립트`로 등록한다. 공유 소비자는 파일 설명을 복사하지 않고 주 소유 문서에 링크한다.

## 계층 분할 기준

세부 기능은 다음 세 조건을 모두 만족하는 책임 단위다.

- 다른 기능과 구분되는 자체 실행 흐름이나 판단 책임이 있다.
- 변경 진입점과 관련 파일 집합을 따로 지정할 수 있다.
- 형제 기능을 수정하지 않고 독립적으로 변경될 수 있다.

한 문서에 독립 세부 기능이 4개 이상 생기면 폴더형 인덱스로 분할한다. 파일 수나 줄 수만으로 분할하지 않는다.

```text
Feature/
  README.md        세부 기능 선택표, 전체 흐름, leaf 간 의존성
  SubFeature.md    실제 흐름, 주 소유 파일, 최소 확인 범위
```

상위 README에는 전체 스크립트 목록을 두지 않는다.

## 작성 규칙

- 현재 구현, 계획, TBD를 같은 문단에 섞지 않는다.
- 긴 코드를 복사하지 않고 symbol과 경로를 적는다.
- line number는 장기 문서에 고정하지 않는다.
- 과거 구현 과정은 `Status`, 완료 계획은 `Archive/Plans`에 기록한다.
- leaf 문서는 250줄 이하를 기본으로 하되 정보 삭제로 수치를 맞추지 않는다.
- 코드와 문서가 다르면 코드를 현재 사실로 보고 같은 변경에서 문서를 교정한다.
