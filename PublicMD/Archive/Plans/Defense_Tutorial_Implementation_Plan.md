# DefenseTest 튜토리얼 구현 계획

사용자가 2026-11-18 승인한 대화 계획. 구현·배선·컴파일·독립 리뷰 완료(실제 Play/화면 미검증). 현재 상태와 실제 검증 결과는 PROGRESS 및 `.harness-runs/tutorial-20261118/work-record.md`를 따른다.

## 확정 동작

- 정식 대화와 연결 연출 전체에서 게임 시간을 멈춘다. 중앙 관리자의 정지 요청을 각각 해제하고 다른 요청이나 GameOver는 유지한다.
- 시작 카메라 상태 저장 → 시청 이동·확대 → 접수원 등장 → 말풍선 인사·수락 질문 → 수락 시 시설 소개 → 접수원 인사 → 문으로 귀환 → 카메라 복구 → 게임 재개.
- 거절하면 시설 소개만 생략한다. 초기 시설·주민·자원 조립은 허용하며 gameplay 시간과 행동은 진행하지 않는다.
- 화자를 직접 비추면 기존 말풍선, 건물 등 다른 대상을 비추면 화자 이름과 대사가 있는 하단창을 사용한다. 이동 중에는 창을 닫는다.
- 입력은 출력 중 전체 표시, 출력 후 다음 줄이다. 출력 완료 후 기본 3초 자동 넘김; 선택지는 응답 대기. 동일 입력의 중복 소비와 배경 게임 입력을 막는다.
- 기본 연출은 첫 이동2초, 건물 이동0.8초, 카메라 복구1.2초, 접수원 등장/귀환 각각1초, 글자당0.025초다. 모두 편집 가능하다.

## 재사용과 편집

- Tutorial 폴더는 시작 연결만 소유한다. 시간·대화 진행·카메라·배우 연출은 공통 기능이다.
- 기존 지역화 CSV에 문구를 저장하고 ScriptableObject에 단계 ID, 다음 연결, 선택지, 표시 방식, 시간과 연출을 둔다. 씬 대상은 별도 ID 바인딩으로 연결한다.
- 대사·순서·대상·카메라 조절은 C# 변경 없이 가능하다. 실행 중 hot reload와 전용 노드 에디터는 제외한다.
- 다음 연결 없음은 종료. 외부 행동 실행과 완료 대기를 지원하지만 퀘스트 시스템 자체는 만들지 않는다.
- DefenseTest는 임시 첫 사례다. 기본 소개는 시청 → 밭 → 창고 → 식당 → 여관 → 초소 → 북쪽 성벽 → 상단 방문 장소다. 상단을 강제 등장시키지 않는다. 현재 없는 주택과 빈 부지는 제외한다.
- 저장/PlayerPrefs는 도입하지 않는다. 지금은 씬 실행마다 자동 시작하며 이를 끄거나 명시 시작할 수 있다. 향후 이어하기에서는 시작 호출을 생략한다.

## 연결과 범위

- 기존 은발 접수원 sprite와 주민 걷기 Animator를 재사용한다. 접수원에는 custom 행동 script/WorkerNPC/NPCComponent를 추가하지 않고 외부 연출 담당이 제어한다.
- 독립 문/대기 anchor를 추가하고 기존 유지보수 anchor 의미를 보존한다.
- UI host는 비활성 DefenseUI와 분리한다. 일반 hover/팝업과 입력을 정리하고 카메라 입력은 연출에 제어권을 양보한다.
- 기존 DefenseGameSession 공개 API와 GameOver 규칙을 유지하면서 공통 시간 관리자로 위임한다. TerrainTest는 해당 공통 관리자 호환 연결만 변경한다.
- 상단 즉시 방문 등 deltaTime 없이 진행 가능한 진입점을 정지 규칙에 맞춘다.

## 역할·검증

코드/그래픽/연결은 각각 author-unity-code, create-project-sprites, assemble-unity-objects의 별도 fresh-context 작업자가 수행한다. 독립 코드/아트 준비는 병렬, 실제 연결은 코드 컴파일 및 에셋 확정 후 수행한다. Editor import/compile/save는 순차 진행한다. 루트는 공통 문서, 조정, diff/증거 확인과 최종 판정을 맡는다.

필수 확인은 컴파일, 기존 지역화·NPC 메시지 검사, 실제 저장 참조/구조, 컨벤션·책임·의존 방향과 독립 후보 리뷰다. 새로운 테스트/하네스, 자동 Play, 게임 화면 검증은 추가하지 않는다. 사람이 수락/거절, 정지 겹침, 입력, UI 전환과 편집 재사용을 확인할 수 있도록 미검증 항목으로 인계한다.
