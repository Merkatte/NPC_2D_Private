# Independent NPC Candidate Review

Root invokes a fresh read-only collaboration agent with `fork_turns="none"` after
the current candidate's required checks succeed. The reviewer must never have been
an implementation/remediation worker for that candidate. Wait for a free slot if
necessary; never repurpose a worker or finish after merely launching review.

Use `reviewing-unity-candidate`, not a new repository-wide audit. Supply original
request, approved scope/exclusions, actual diff (including new files), directly
relevant Systems/CodeConvention/architecture rules and current compile/scope/reference
evidence. Include a passing GateResult and pinned envelope only when that workflow
was selected. Supply primary evidence, not the author's narrative or conclusions.

For every C# change, independently check conventions, responsibility/owning leaf and
actual dependency direction, with code/document locations. Check affected lifecycle,
pooling, transaction and serialization concerns by reading relevant code. Automatic
Play Mode and game-screen verification remain excluded under SceneWork.md.

Return the ordinary or selected-gate record specified by reviewing-unity-candidate.
Root persists the record under the run evidence path, checks identity/freshness and
coverage, and waits for an eligible approval. Missing evidence or blocking findings
prevent completion. Assign fixes to the original role; reviewer stays read-only.
One reviewer covers the relevant categories; no second full audit is required.

Do not invoke the legacy background launcher or overwrite
`PublicMD/Status/Code_Evaluation_Result.md` for this bounded review. That report and
the retained launcher scripts belong to their explicitly selected audit/legacy use.
